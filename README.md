# DeepShield

**개인 딥페이크 신원 보호 및 다중 신호 탐지 시스템**

DeepShield는 사용자의 얼굴 이미지에 서로 독립적인 보호 계층을 적용한 뒤, 의심스러운
이미지와 영상에서 그 사용자와 생체적으로 유사한 콘텐츠를 분석하고, 여러 포렌식
신호를 하나의 설명 가능한 위험도 평가로 융합합니다.

**상태: Phase 0–15 구현 및 측정 완료.** 얼굴 검출, 정렬, 임베딩, 등록, 매칭, 이미지 및
영상 분석, 딥페이크 어댑터, 핑거프린팅, 워터마킹, 위험도 엔진, 보호 파이프라인,
적대적 클로킹 연구, 강건성 벤치마크, REST API, 출처(provenance)가 모두 동작합니다.
이 README의 모든 수치는 이 저장소의 코드가 산출한 것이며, 그 수치를 만들어내는
명령어를 함께 적어두었습니다.

**이 시스템을 사용하거나 확장하기 전에 [동작하지 않는 것](#동작하지-않는-것)을 먼저
읽으십시오.** 다섯 개의 증거 신호 중 셋은 동작하고 측정되었으며, 하나는 계산은 되지만
의도적으로 점수에서 제외되고, 보호 계층 하나는 효과가 없다고 측정되었습니다.

## 동작하지 않는 것

아래는 전부 측정된 결과이지 미완성 기능이 아닙니다. 해당 코드 경로는 존재하고,
테스트되어 있으며, 자기 자신을 과장하기를 거부합니다 — 낙관적인 기본값 뒤에 숨기지 않고
여기에 나열한 이유가 그것입니다.

### 신호별 상태

| 신호 | 상태 | 측정값 | 비고 |
|---|---|---|---|
| 신원 유사도 | ✅ 동작 | EER 0.0000, 진짜 850건 대 사칭 24,650건 | 점수 반영, 가중치 재정규화 |
| 워터마크 귀속 | ✅ 동작 | 2,550회 측정 중 잘못된 코드 0건 | 점수 반영 |
| 지각적 핑거프린트 | ✅ 동작 | 정확 일치 및 근사 중복 매칭 | 증거 임계값 초과 시에만 점수 반영 |
| 출처(Provenance) | ✅ 동작 | 로컬, 자가 주장 계보 | 점수 반영 |
| **합성 미디어(딥페이크)** | ⛔ **점수 미반영** | 4회 시도 중 최고: **AUC 0.59** | 계산하고 보고하되 위험 점수에서 제외 |
| **적대적 클로킹** | ⛔ **효과 없음** | 임베딩 변위가 **JPEG보다도 작음** | 기본 비활성화, 연구용으로 보존 |

### 1. 딥페이크 신호는 위험 점수에서 제외됩니다

네 번 시도했고, 쓸 만한 것은 하나도 없었습니다.

| 시도 | ROC-AUC | 실제 사진에 대한 오탐 |
|---|---|---|
| 직접 만든 블렌딩 탐지기 | 0.579 (표본 내 0.641) | — |
| `Wvolf/ViT_Deepfake_Detection` | 0.594 | **76.3%** |
| `dima806/deepfake_vs_real_image_detection` | 0.586 | **70.4%** |
| `prithivMLmods/Deep-Fake-Detector-Model` | 0.385 (우연 수준 이하) | 45.6% |

가장 성능이 좋은 두 공개 모델이 **진짜 사진 열 장 중 일곱 장을 합성이라고 판정**합니다.
따라서 위험도 엔진은 이 신호에 점수 매기기를 거부하고,
`evaluate_deepfake_detectors.py --write`도 이들 중 어느 것도 채택하지 않습니다.

**무엇이 막고 있는가:** 실제 라벨링된 코퍼스(FaceForensics++, Celeb-DF, DFDC)로 학습된
탐지기입니다. 셋 다 서명된 데이터 사용 동의서를 요구하며, 이는 이 저장소가 스스로
밟을 수 없는 유일한 단계입니다. 모델만 생기면 나머지는 이미 다 만들어져 있습니다.

```bash
python scripts/fetch_deepfake_detector.py --model <hf-repo-or-path>
python scripts/evaluate_deepfake_detectors.py --write   # 기준을 통과할 때만 채택합니다
```

기준은 오탐률 10% 이하에서 ROC-AUC 0.75 이상입니다.

### 2. 적대적 클로킹은 보호해주지 않습니다

지각적으로 수용 가능한 예산(ε=0.03)에서 클로크는 얼굴 임베딩을 코사인 거리 0.016만큼
이동시키는 반면, 단순한 JPEG-70은 0.022, 50% 리사이즈는 0.046만큼 이동시킵니다.
모델 간 전이는 여기서 다시 세 배 더 약해집니다. ε=0.06에서는 이미지가 눈에 띄게
열화되고(SSIM 0.873) 그럼에도 인식은 0.97 유사도로 여전히 성공합니다.

기본값은 `enabled: false`이며 연구용으로 문서화되어 있습니다. **이것은 버그가 아니라
발견입니다** — 보호를 기대하고 활성화하지 마십시오.

### 3. 워터마크의 한계

복원됨: JPEG q90/q70, WebP, 블러, 노이즈, 밝기, 대비, 스크린샷, 75% 리사이즈,
10%·20% 크롭. **복원 실패: 회전, 25% 리사이즈, 그리고 작은 이미지에서는 30% 크롭과
JPEG q50.** 해상도가 중요합니다. 30% 크롭은 512픽셀 이미지에서는 살아남지만
250픽셀 이미지에서는 살아남지 못합니다.

**회전을 풀려면:** 로그-극좌표 또는 푸리에-멜린 동기화, 혹은 기존 그리드 탐색에 회전
스윕을 추가하면 됩니다. 후자는 약 30분 작업이지만 탐색 공간을 배로 늘리고, 개발 중
잘못된 귀속을 만들어낸 것이 바로 그 탐색 공간이었습니다 — 그러므로 코드만이 아니라
동일한 측정 규율이 함께 필요합니다.

### 4. 캘리브레이션은 잠정적입니다

임계값은 Labeled Faces in the Wild의 30개 신원으로 적합시켰습니다. 이 벤치마크는 인구
통계와 포즈에서 편향되어 있고, 동일 신원 내 비교는 서로 독립적이지 않습니다.

**무엇이 막고 있는가:** 배포 대상 집단과 닮은 사진으로 재적합하는 것입니다. 그런
사진만 있으면 몇 분이면 끝납니다.

```bash
python scripts/build_evaluation_set.py       # 또는 직접 라벨링한 세트를 지정하십시오
python scripts/calibrate_thresholds.py --write
```

### 5. 설계상 범위 밖

- **학습 데이터 귀속** — 여기 있는 어떤 기법으로도 증명할 수 없으며, 시스템은 결코
  그렇게 주장하지 않습니다.
- **웹 모니터링 / 크롤링** (Phase 16) — 인터페이스만 존재합니다. 입력은 사용자가
  제출한 것뿐입니다.
- **완전한 C2PA** — 선언된 스텁입니다. `verify()`는 `supported: false`를 반환하므로
  호출자가 "자격증명 없음"과 "확인 불가"를 구분할 수 있습니다.

### 실제 사용자를 대상으로 배포하기 전에

- [ ] 대표성 있는 사진으로 임계값 재적합 (위 §4)
- [ ] 기준을 통과하는 딥페이크 탐지기를 확보해 연결하거나(위 §1), 합성 미디어 신호가
      없다는 사실을 받아들일 것
- [ ] 직접 재측정하지 않았다면 적대적 클로킹은 비활성화 상태로 둘 것
- [ ] 워터마크의 회전 취약점이 당신의 유통 채널에서 문제가 되는지 판단할 것

## 프로젝트 목표

실제 코드와 실제 측정으로 하나의 연구 질문에 답하는 것입니다.

> 사용자의 얼굴 이미지에 보호를 적용한 뒤, 그 사용자와 얼굴 유사도가 높은 콘텐츠를
> 탐지하고, 그 콘텐츠가 합성일 가능성을 — 하나가 아니라 여러 개의 독립적인 증거로 —
> 평가할 수 있는가?

목표는 "딥페이크를 막는" 프로그램이 **아닙니다**. 신원 보호, 멀티미디어 포렌식,
적대적 ML, 콘텐츠 출처의 교차점에 있는 개인 신원 보호 시스템입니다.

---

## 위협 모델

**누구를 보호하는가.** 얼굴 사진을 공개적으로 게시하는 개인.

**공격자는 무엇을 하는가.** 그 사진들을 수집해 해당 인물의 합성 이미지나 영상을
제작하고 재유포합니다. 무엇이든 재인코딩, 크롭, 리사이즈, 스크린샷, 색 보정, AI
업스케일할 수 있으며, 워터마크를 의도적으로 제거하고 클로킹을 무력화하려 시도할 수
있습니다.

**우리가 통제하는 것.** 사용자가 게시 전에 보호하는 이미지, 그리고 이후 분석을 위해
제출되는 콘텐츠.

**우리가 통제하지 못하는 것.** 공격자의 모델과 파이프라인, 그리고 등록 이전에 이미
공개된 사용자 사진의 모든 사본.

**귀결.** 모든 개별 신호는 각각 독립적으로 파괴될 수 있습니다 — 이는 가정이 아니라
아래에서 측정된 사실입니다. 시스템이 단일 탐지기가 아니라 다중 신호 증거 융합으로
설계된 이유가 그것입니다.

## 이 시스템이 탐지할 수 있는 것

- 제출된 미디어 속 얼굴이 등록된 신원과 **생체적으로 높은 유사도**를 갖는지 여부.
- **DeepShield 워터마크**가 복원 가능한지, 그리고 어느 유통 채널로 발급된 것인지.
- 파일이 등록된 보호 자산의 **정확한 사본 또는 지각적 근사 중복**인지 여부.
- 교체 가능한 탐지기가 산출하는 **합성 미디어 가능성 점수**.
- 어떤 증거가 점수를 움직였는지 명시하는, 종합적이고 설명 가능한 **위험 점수**.

양성 결과에 대한 올바른 표현이자 코드가 실제로 출력하는 문장입니다.

> 등록된 신원 'curie'와 높은 유사도(0.995)를 갖는 얼굴이 포함된 콘텐츠가 발견되었습니다.
> 합성 미디어 탐지기는 0.763점을 부여했습니다. 이는 가능성이지 확정이 아닙니다.
> DeepShield 워터마크(46940c50)가 복원되었으며, 이는 해당 파일이 등록된 보호 자산에서
> 파생되었음을 시사합니다.

## 이 시스템이 증명할 수 없는 것

> **이 시스템은 특정 이미지가 생성 모델의 학습 데이터로 사용되었음을 증명할 수 없습니다.**

또한 다음도 확립할 수 없으며, 코드는 결코 이를 주장하지 않습니다.

| 주장 | 성립하지 않는 이유 |
|---|---|
| "워터마크는 그 이미지로 만든 딥페이크에도 남는다." | 워터마크는 신원이 아니라 파일을 보호합니다. 생성 모델은 워터마크를 재현하지 않습니다. |
| "적대적 섭동은 모든 모델에 통한다." | 아래에서 측정됨: 수용 가능한 품질의 클로킹은 임베딩을 *JPEG 압축보다도 적게* 이동시킵니다. |
| "딥페이크 탐지기가 모든 생성기를 잡아낸다." | 탐지기는 보지 못한 생성기 계열로 잘 일반화되지 않습니다. 우리 것은 캘리브레이션되지 않았고 점수에서 제외됩니다. |
| "얼굴 유사도가 높으면 그 콘텐츠는 딥페이크다." | 유사도는 신원 신호입니다. 사용자의 진짜 사진이 무엇보다 높은 점수를 받습니다. |
| "딥페이크 점수가 높으면 사용자의 사진이 학습 데이터였다." | 완전히 다른 문제입니다 — 그것은 멤버십 추론입니다. |
| "지각적 해시로 이미지를 생성 결과물까지 추적할 수 있다." | pHash는 파일의 사본을 추적할 뿐, 모델 내부의 신원을 추적하지 않습니다. |

**문제 A(학습 데이터 귀속)** 는 범위 밖입니다.
**문제 B(신원 유사도 탐지)** 가 MVP이며, 이는 동작합니다.

 Watermark Fingerprint Adversarial

**후보 게이팅**이 이 시스템을 감당 가능하게 만들고 오탐을 억제합니다. 신원 유사도가
먼저 저렴하게 실행되고, 후보 임계값을 넘은 얼굴만 딥페이크 탐지기에 도달합니다.
모르는 사람의 합성 이미지는 이 사용자의 문제가 아니며, 그것에 점수를 매겨봐야 잡음만
늘어납니다.

### 구조

```text
src/deepshield/
├── cli.py            명령 표면과 종료 코드
├── config.py         타입이 있는 YAML 설정. 하드코딩된 임계값 없음
├── logging_utils.py  로깅 및 생체정보 마스킹
├── registry.py       이름 → 백엔드 팩토리. 모델 교체 가능성 유지
├── types.py          공용 데이터 구조와 그 JSON 형태
├── media.py          디코딩, 저장, 해싱
├── quality.py        PSNR, SSIM, 선명도
├── transforms.py     공용 변환 엔진
├── experiments.py    재현 가능한 벤치마크
├── models.py         체크섬으로 고정된 가중치 다운로드
├── face/             detector · aligner · embedder · matcher · enrollment · backends
├── protection/       watermark · fingerprint · adversarial
├── detection/        deepfake · deepfake_backends · watermark_detector · manipulation
├── video/            sampler · tracker · processor
├── provenance/       hash_chain · metadata · c2pa_adapter
├── risk/             features · scorer · calibration
├── storage/          신원·자산·증거·출처 저장소
├── pipeline/         protection_pipeline · analysis_pipeline
└── api/              app · routes
```

교체 가능한 모든 모델은 레지스트리를 통해 해석되는 추상 인터페이스 뒤에 놓이므로,
어떤 단계도 특정 벤더에 용접되어 있지 않습니다.

## 설치

Python 3.11 이상이 필요합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev,face,video,api,experiments]"
./bin/deepshield download-models --insightface
```

모델 가중치는 이 저장소에 커밋되어 있지 않습니다 — ONNX 탐지기 샤드가 각각 327MB로
GitHub의 100MB 파일 한도를 넘습니다 — 따라서 위 다운로드 단계는 선택이 아니라
필수입니다. 이 명령은 체크섬으로 고정된 YuNet·SFace 가중치와 InsightFace 팩을 원
배포처에서 받아옵니다. 공개된 딥페이크 탐지기는 별도로 내보냅니다. 받아올 파일이
아니라 ONNX로 변환해야 하는 Hugging Face 체크포인트이기 때문입니다.

```bash
python scripts/fetch_deepfake_detector.py --model dima806     # 그 외: wvolf, prithiv
```

각 모델 옆의 메타데이터 JSON(`models/deepfake_<name>.json`)만 커밋되어 있습니다. 이
파일에는 전처리 규약이 기록되어 있고, 측정된 AUC는
`data/results/deepfake_detector_survey.json`에 남아 있습니다. 그래서 이 저장소는 모델
자체를 동봉하지 않고도 어느 것도 사용할 수 없다고 말할 수 있습니다.

### 또는: 릴리즈에서 고정된 가중치 내려받기

이 프로젝트가 측정에 사용한 모든 가중치는
[`models-v1` 릴리즈](https://github.com/LH-GWAN/deepfake-found/releases/tag/models-v1)에
첨부되어 있습니다. PyTorch 설치나 Hugging Face 왕복 없이 새 체크아웃을 한 번에
실행 가능한 상태로 만들 수 있습니다.

```bash
gh release download models-v1 --repo LH-GWAN/deepfake-found --dir models
mkdir -p models/insightface/models && mv models/buffalo_l.zip models/insightface/models/
shasum -c models/SHA256SUMS.txt      # 저장소 루트에서 실행하십시오
```

`gh`가 없다면 각 자산은
`https://github.com/LH-GWAN/deepfake-found/releases/download/models-v1/<name>`
형태의 평범한 URL입니다.

| 자산 | 놓을 위치 | 크기 |
|---|---|---|
| `deepfake_dima806.onnx` + `.onnx.data` | `models/` | 328 MB |
| `deepfake_prithiv.onnx` + `.onnx.data` | `models/` | 328 MB |
| `deepfake_wvolf.onnx` + `.onnx.data` | `models/` | 328 MB |
| `face_detection_yunet_2023mar.onnx` | `models/` | 227 KB |
| `face_recognition_sface_2021dec.onnx` | `models/` | 37 MB |
| `buffalo_l.zip` | `models/insightface/models/` | 275 MB |

`.onnx` 그래프와 그 `.onnx.data` 샤드는 하나의 모델입니다. ONNX Runtime이 그래프가
있는 디렉터리에서 파일명으로 샤드를 찾으므로, 둘은 반드시 `models/` 아래에 함께 놓이고
이름을 유지해야 합니다. 이 README의 수치가 측정된 바로 그 그래프가 필요하다면 이
경로를 택하십시오 — 원 배포처에서 다시 내보낸 결과는 바이트 단위로 동일하지 않을 수
있습니다. 라이선스는 각 원 프로젝트를 따릅니다.

기본 임베더는 ArcFace이며 InsightFace 모델 팩이 필요합니다. 팩이 없으면 파이프라인은
모델이 없다고 보고하고 가져올 명령을 알려줍니다. 대신 37MB 폴백으로 돌리려면
`face.embedder.backend: opencv_sface`로 설정하십시오.

Extras: `face` (OpenCV, ONNX Runtime, InsightFace), `video` (OpenCV, PyAV),
`api` (FastAPI, SQLAlchemy), `experiments` (pandas, scikit-learn, matplotlib),
`torch` (향후 학습 기반 워터마킹용). `deepshield doctor`가 현재 설치된 것을 보고합니다.

### `./bin/deepshield`를 사용하십시오

`bin/deepshield`는 `PYTHONPATH`를 설정하고 `python -m deepshield`를 실행합니다. 콘솔
스크립트보다 이쪽을 권합니다. macOS에서 iCloud나 OneDrive로 동기화되는 폴더에 있을 때,
`pip install -e`가 기록한 `.pth` 파일이 인터프리터 기동 중 간헐적으로 무시되어 콘솔
스크립트가 `ModuleNotFoundError: No module named 'deepshield'`로 실패합니다. 런처와
Makefile 타깃은 영향을 받지 않습니다. 저장소를 동기화 폴더 밖의 ASCII 경로에 두면 이
문제는 완전히 사라집니다.

가중치는 결코 커밋되지 않습니다. `src/deepshield/models.py`에 URL과 SHA-256으로
고정되어 있으며 다운로드 시 검증됩니다. 모델 이름과 버전이 모든 결과에 기록되므로,
과거 분석은 재현 가능한 상태로 남고 실수로 다른 모델끼리 비교한 경우를 탐지할 수
있습니다.

ArcFace가 기본인 이유는 명확히 더 낫다고 측정되었기 때문입니다. 아래 **정밀도**를
참고하십시오. SFace는 추가 파이썬 패키지가 필요 없는 37MB 폴백으로 남아 있습니다.

**검출기 비교.** 일반적으로는 SCRFD가 더 강한 모델이지만, *여기서는* YuNet이 더 낫다고
측정되었기 때문에 YuNet이 기본입니다.

| 검출기 | 원본 | 20% 크롭 | 블러 σ=3 | 스크린샷 |
|---|---|---|---|---|
| YuNet | 170개 중 0개 놓침 | **170개 중 0개 놓침** | 170개 중 0개 놓침 | 170개 중 0개 놓침 |
| SCRFD (InsightFace) | 1개 놓침 | **170개 중 167개 놓침** | 1개 놓침 | 1개 놓침 |

크롭된 프로브의 98%를 놓치는 검출기는 모든 크롭을 "증거 없음" 결과로 바꿔버립니다.
설정은 평판이 아니라 측정을 따릅니다.

## 위험 점수

위험도 엔진은 신호들을 하나의 설명 가능한 평가로 융합합니다. 세 가지 규칙이 이를 단순한
숫자가 아니라 방어 가능한 결과로 만듭니다.

**없음은 0이 아니다.** 계산할 수 없었던 신호는 `None`으로 남습니다. *실제로* 계산된
신호들의 가중치가 재정규화되므로, 확인할 수 없었던 워터마크는 위험도가 아니라 커버리지를
낮춥니다.

**귀속 신호는 양성 증거만 반영한다.** 공격자는 워터마크를 제거할 수 있으므로 양성 탐지만
기여합니다. 지각적 핑거프린트도 마찬가지입니다. 서로 무관한 두 이미지도 해시 비트의 절반
정도는 우연히 일치하므로, 증거 임계값 미만의 유사도는 보고는 되지만 점수에는 반영되지
않습니다.

**캘리브레이션되지 않은 신호는 보고하되 점수에 넣지 않는다.** 임계값이 한 번도 적합된 적
없는 탐지기가 내놓는 숫자에는 정의된 동작점이 없습니다. 그것을 포함하는 것은 추측을
백분율로 세탁하는 일입니다.

세 규칙이 한꺼번에 드러나는, 무관한 인물에 대한 실제 출력입니다.

```text
risk score: 19 / 100  (LOW)
  face_similarity: 0.187 (weight 100%, contributes 18.7 points)
  watermark: not detected, treated as neutral rather than exculpatory

limitations:
  - Face similarity does not prove that an image was used as training data.
  - Only 40% of the intended signal weight was available; the score is computed
    over the signals that were present.
  - The closest registered asset matched at 0.562 perceptual similarity, below
    the 0.812 evidence threshold. Unrelated images score around 0.5 by chance,
    so this was reported but not counted toward the risk score.
  - The synthetic-media detector was not run: no face passed the identity
    candidate threshold, so there was nothing to attribute to this user.
```

## 정밀도

사용자가 실제로 행동에 옮기는 산출물은 신원 주장이므로, 파이프라인은 정확도가 아니라
정밀도에 맞춰 튜닝되어 있습니다. 이를 희망이 아니라 측정 가능한 것으로 만드는 요소는 셋
입니다. 설정 간 차이를 가를 만큼 충분히 큰 평가 세트, 시스템이 실제로 하는 일과 일치하는
프로토콜, 그리고 그 결과 위에서 적합된 임계값입니다.

### 프로토콜

```bash
python scripts/build_evaluation_set.py --identities 30 --per-identity 8
python scripts/evaluate_face_pipeline.py --embedders opencv_sface insightface \
    --tta 0 1 --ensemble --target-precision 0.99
python scripts/calibrate_thresholds.py --write
```

평가 세트는 Labeled Faces in the Wild의 30개 신원에 걸친 170장의 사진이며, 선명한 얼굴이
정확히 하나만 있는 이미지로 필터링했습니다. 매칭은 leave-one-out으로 평가합니다. 각 사진이
프로브가 되고, 그 신원의 나머지 사진이 갤러리를 이루며, 다른 모든 신원이 사칭 갤러리를
구성합니다. **프로브는 열화시키되 갤러리는 열화시키지 않습니다** — 등록 사진은 사용자가
고르지만, 의심 콘텐츠는 재인코딩되거나 크롭되거나 스크린샷된 채로 도착하기 때문입니다.
이 비대칭성이 비교를 의미 있게 만들기도 합니다. 깨끗한 정면 인물 사진에서는 여기 있는 모든
백엔드가 완벽한 AUC를 기록해 서로 구분할 수 없습니다.

### 백엔드 비교

다섯 가지 프로브 조건에 걸쳐 통합, 진짜 850건과 사칭 24,650건 비교:

| 임베더 | 통합 EER | 진짜 최솟값 | 사칭 최댓값 | 분리 가능 |
|---|---|---|---|---|
| SFace 128차원 | 0.0012 | 0.304 | 0.488 | **아니오 — 분포가 겹침** |
| SFace + flip-TTA | 0.0010 | 0.311 | 0.488 | 아니오 |
| **ArcFace 512차원 + flip-TTA** | **0.0000** | **0.440** | **0.332** | **예, 간격 0.107** |

조건별, 정밀도 0.99 이상에서의 평균 재현율:

| 프로브 조건 | SFace | SFace+TTA | ArcFace | ArcFace+TTA |
|---|---|---|---|---|
| 원본 | 1.000 | 1.000 | 1.000 | 1.000 |
| JPEG q30 | 1.000 | 1.000 | 1.000 | 1.000 |
| 20% 크롭 | 0.994 | 1.000 | 1.000 | 1.000 |
| 가우시안 블러 σ=3 | 0.994 | 0.994 | 1.000 | 1.000 |
| 스크린샷 (0.6×, q60) | 1.000 | 1.000 | 1.000 | 1.000 |
| **평균** | 0.998 | 0.999 | **1.000** | **1.000** |

세 가지 결론을 내렸고, 모두 실제로 반영했습니다.

- **ArcFace가 SFace를 대체해 기본값이 되었습니다.** 열화 조건에서 진짜 분포와 사칭
  분포가 겹치지 않는 유일한 설정입니다.
- **Flip-TTA는 기본 활성화입니다.** 순전파 한 번의 비용이 추가되며 SFace의 20% 크롭
  격차를 메웠습니다. ArcFace에서는 측정 가능한 변화가 없었고, 그래서 주장이 아니라
  조절 손잡이로 남겨두었습니다.
- **ArcFace와 SFace의 앙상블은 평가 후 기각했습니다.** 두 배의 비용으로 ArcFace 단독과
  같은 성능을 냈습니다. 두 번째 모델이 실제로 도움이 되는 경우를 위해 융합 기능
  자체는 남아 있습니다(`face.embedder.ensemble`).

집계 전략도 같은 데이터로 비교했으며 여기서는 통계적으로 구분되지 않았습니다(평균 EER이
`centroid` 0.00040, `max`와 `topk_mean` 0.00041). 그래서 근거 없이 바꾸지 않고 `max`를
유지했습니다.

파이프라인을 완전히 무력화하는 조건이 하나 있습니다. **250픽셀 이미지를 25%로 축소하면
검출이 아예 되지 않았고**, 따라서 틀린 점수 대신 아무 점수도 내지 않습니다. 검출 실패와
오식별은 원인도 해법도 다르기 때문에 문서 전반에서 따로 보고합니다.

### 임계값 배치

분포가 분리되면, 두 경계 모두 어느 한쪽 분포의 가장자리가 아니라 간격의 중점을 기준으로
배치합니다.

```text
사칭 최대 0.3323 ──┬── 0.3591 candidate ── 0.3860 중점 ── 0.4128 high ──┬── 0.4397 진짜 최소
                   └──────────────── 간격 0.1074 ──────────────────────┘
```

경계를 가장 낮은 진짜 점수에 두면 측정된 데이터에서는 완벽한 점수가 나오지만 여유가 전혀
없습니다 — 다음번의 조금 더 어려운 진짜 쌍이 그대로 뚫고 떨어집니다. 각 임계값은 중점에서
간격의 4분의 1만큼 떨어져 있으므로, `candidate`는 놓치지 않는 쪽으로,
`high_confidence`는 확실한 쪽으로 기웁니다. 현재 두 임계값 모두 25,500회 비교에서 오탐
없이 정밀도 1.000, 재현율 1.000에 도달합니다.

### 2단계 신원 판정

후보 임계값을 넘었다는 것은 그 얼굴에 비싼 탐지기를 쓸 만하다는 근거가 됩니다. 사용자에게
당신의 얼굴이 발견되었다고 말할 근거는 **되지 못합니다**. `matched_user_id`는
high-confidence 판정에서만 채워지며, 네 가지 상태가 각각 구분되어 보고됩니다.

| 판정 | 의미 | 보고 방식 |
|---|---|---|
| `no_match` | 후보 임계값 미만 | 신원 결론 없음 |
| `candidate` | 후보 이상, 고신뢰 미만 | "검토할 가치는 있으나 일치는 아님" |
| `ambiguous` | 1위와 2위 신원이 `min_margin` 이내 | "어느 쪽도 특정하기엔 격차가 너무 작음" |
| `high_confidence` | 임계값 초과, 모호하지 않음 | 신원을 명시 |

두 가지 가드가 이를 뒷받침합니다. 1위와 2위 신원 사이의 **마진**은 근소한 동점을
강등시킵니다. 한 신원에 0.62, 다른 신원에 0.61을 기록한 프로브는 절댓값이 아무리 높아
보여도 아무도 식별하지 못한 것입니다. 관측된 정답 식별 마진은 0.431 아래로 내려간 적이
없으므로, 0.05 가드는 이 데이터에서 아무 비용도 들지 않고 진짜 모호한 경우에만
발동합니다. 신원이 하나만 등록된 흔한 개인 사용 사례에서는 비활성 상태나 마찬가지입니다.

**프로브 품질** 점수는 임베더의 112픽셀 입력 대비 얼굴 해상도와, 깨끗한 크롭의 측정된
중앙값 대비 크롭 선명도를 결합해 둘 중 나쁜 쪽을 취합니다. 프로브가 얼마나 신뢰할 수
없는지에 비례해 판정 임계값을 올릴 수 있습니다. 켜기 전에 그 비용을 측정했습니다.

| 조건 | 품질 중앙값 | 가드 없는 재현율 | 0.10 가드 적용 재현율 |
|---|---|---|---|
| 원본 / JPEG / 스크린샷 | 0.83 – 1.00 | 1.000 | 1.000 |
| 가우시안 블러 σ=3 | 0.036 | 1.000 | **0.894** |

이 파이프라인에서 가드는 재현율만 깎을 뿐 어떤 오탐도 막지 못합니다. ArcFace가 이미 블러
조건에서 완벽하게 분리하기 때문입니다. **따라서 기본 비활성화**이며
(`low_quality_penalty: 0.0`), 흐린 프로브가 실제로 사칭 분포와 겹치는 더 약한 임베더를
위해 문서화된 손잡이로 남겨두었습니다. 품질 점수 자체는 모든 얼굴에 대해 계속 계산되고
보고됩니다.

### 위험 점수에 미친 영향

기본 임베더를 바꾸자 무관한 인물의 점수가 0.187에서 0.056으로 내려갔고, 이는 위험도
출력에 그대로 전파됩니다.

```text
변경 전 (SFace)   tesla_1.jpg vs 등록된 'curie'   유사도 0.187   위험도 19 LOW
변경 후 (ArcFace) tesla_1.jpg vs 등록된 'curie'   유사도 0.056   위험도  6 LOW
```

### 이 수치들이 의미하지 않는 것

LFW는 보도 사진에서 수집되었고 인구 통계와 포즈에서 편향되어 있습니다 — 이는 그
제작자들이 직접 밝힌 사실입니다. 한 신원 내부의 비교는 서로 독립적이지 않으므로, 진짜
비교 850건이 850건어치의 증거를 갖지는 않습니다. 이 결과는 이 집단 위에서 설정들의 순위를
매기고 잠정적인 경계를 놓을 뿐입니다. 특정 사용자에 대한 정확도 주장이 아니며,
캘리브레이션 보고서는 모든 값 뒤에 있는 신원 수와 사진 수를 기록하므로 그 한계가 숫자와
함께 따라다닙니다.

### 워터마크 재동기화

DCT 워터마크는 원래 모든 기하학적 공격에서 무너졌습니다. 크롭은 디코더가 의존하는 8x8
블록 그리드를 이동시키고 재스케일하기 때문입니다. 세 가지 변경으로 이를 회복했습니다.

**타일 비트 레이아웃.** 비트가 래스터 순서로 할당되어 있었고, 이는 매핑을 이미지 너비에
묶습니다 — 그런데 크롭은 너비를 바꾸므로, 그리드를 찾아냈더라도 모든 비트가 뒤섞입니다.
이제 비트는 반복되는 8x8 타일 내부의 위치로 할당되며, 이는 너비와 무관합니다.

**그리드 탐색.** 디코더는 일곱 가지 배율과 64가지 서브블록 픽셀 오프셋을 모두 시도하며
블록의 부분표본으로 각각을 채점한 뒤, 최상위 후보들에 대해 64가지 타일 위상을 모두
시도합니다.

**더 넓은 체크섬, 그리고 제한된 탐색.** 후보가 하나 늘어날 때마다 잡음에서 체크섬이
통과할 기회도 하나 늘어납니다. 원래 탐색에 CRC-8을 쓰면 **워터마크 없는 이미지 40장에서
오탐 37건**이 나왔습니다. CRC-16은 그것을 해결했지만 그리드 탐색을 감당하지 못했습니다.
CRC-32는 감당할 수 있고, 체크섬은 벡터화된 테이블 기반 구현으로 검증하므로 탐색이 몇 분이
아니라 약 0.3초 걸립니다.

그럼에도 탐색은 두 번 더 제한해야 했고, 두 번 모두 이론이 아니라 측정에 근거했습니다.

- **그리드 탐색 내부의 비트 플리핑은 비활성화했습니다.** 크롭된 이미지 60장 중 동일하게
  57장을 복원하면서 이미지당 후보 메시지를 1만 6천 개 추가했습니다. 한 장 더 복원하는
  것은 잘못된 채널 귀속 한 건의 값어치가 없습니다.
- **유효한 모든 후보가 같은 코드를 지목해야 합니다.** 잘못된 타일 위상에서 나온 후보는
  무작위 비트가 아니라 실제 메시지의 순열이므로, 체크섬이 균등 분포 가정의
  40억분의 1보다 훨씬 자주 통과합니다. 2,550회 측정 벤치마크에서 우연한 통과가 정확히
  한 건 나왔습니다. 검증에 성공한 모든 위상을 수집해 둘이 어긋나면 기각하는 방식으로
  이를 제거했습니다. 이 가드는 크롭된 이미지 170장에서 두 번 발동했고 둘 다 정직한
  미탐지로 바꾸었으며, 대가는 복원 이미지 한 장이었습니다.

512픽셀 합성 기준 이미지, 강도 0.16에서의 결과(PSNR 35.7dB, SSIM 0.927):

| 변환 | 이전 | 이후 |
|---|---|---|
| JPEG q90/q70, WebP, 블러, 노이즈, 밝기, 대비, 스크린샷 | 복원 | 복원 |
| 75% / 50% 리사이즈 | 복원 | 복원 |
| **JPEG q50** | 실패 | **복원** |
| **10% / 20% / 30% 크롭** | 실패 | **복원** |

해상도가 중요하며, 정직한 숫자는 실제 사진에서 나온 숫자입니다. 합성 기준 이미지의 블록
예산 4분의 1에 해당하는 250픽셀 LFW 이미지 170장에서는 아홉 가지 변환이 완벽하게
복원되고, 크롭은 10%와 20%에서는 복원되지만 30%에서는 안 되며, 50% 리사이즈는 대략

작은 이미지는 블록 수가 적으므로 메시지 비트마다 투표가 줄고, 재동기화 탐색이 붙잡을
신호도 적어집니다. 이 세트에서의 삽입 비용은 PSNR 36.2dB, SSIM 0.909입니다.

여기까지 오기 위해 게이트 하나를 제거해야 했습니다. 소프트 디코딩이 투표 일치도에
게이팅되어 있었는데, 이 값은 대다수 비트가 여전히 정확한 상황에서도 축소 변환에서
무너집니다 — 게이트가 유효 판정에서 두 비트 떨어진 디코드를 기각하고 있었습니다. 32비트
체크섬은 정답을 기각하는 휴리스틱보다 나은 가드입니다.

### 딥페이크 신호: 부정적 결과

합성 미디어 점수는 계산은 되지만 결코 점수에 반영되지 않는 유일한 신호였습니다. 임계값이
한 번도 적합된 적이 없었기 때문입니다. 적합에는 라벨 데이터가 필요하므로, 이번에는 직접
만들어서 시도했습니다.

```bash
python scripts/build_manipulation_set.py      # 진짜 169장 + 얼굴 교체 169장
python scripts/train_deepfake_detector.py --write
```

조작 세트는 그래픽 기반 얼굴 교체입니다. 106개 랜드마크의 들로네 메시 위로 공여자 얼굴을
대상에 워핑하고, 색을 맞춘 뒤, 푸아송 블렌딩으로 합성했습니다. 공여자는 포즈 유사도로
고릅니다. 4분의 3 측면 얼굴을 정면 얼굴에 워핑하면 어떤 공격자도 게시하지 않을, 그리고
어떤 탐지기도 잡았다고 인정받아서는 안 되는 결과물이 나오기 때문입니다.

탐지기는 손으로 설계한 열한 개의 블렌딩 아티팩트 특징입니다. 노이즈 잔차, 선명도, JPEG
블록성, 스펙트럼 기울기, 색 통계, 이음매 엣지 에너지를 각각 얼굴 크롭의 중앙부와 테두리
사이의 비율로 계산하고, 로지스틱 회귀에 넣어 **신원이 겹치지 않는** 분할로 평가했습니다.

**동작하지 않습니다.**

| 분할 | ROC-AUC |
|---|---|
| 학습에 없던 신원, 원본 | 0.579 |
| 학습에 없던 신원, JPEG q50 | 0.536 |
| 학습에 없던 신원, 50% 리사이즈 | 0.545 |
| **표본 내** (특징이 애초에 적합되기는 하는가?) | **0.641** |
| 최고 단일 특징 (내부 노이즈) | 0.601 |

정보를 주는 숫자는 표본 내 값입니다. 0.64라면 정답을 눈앞에 두고도 특징이 과제에 적합되지
못한다는 뜻이므로, 이는 과적합이나 분할 문제가 아니라 특징 자체가 부적절하다는 뜻입니다.
이유는 기계적입니다. 푸아송 블렌딩은 정확히 이음매의 기울기 불연속을 없애기 위해 존재하며,
이 특징들 대부분이 측정하는 것이 바로 그 불연속입니다.

두 가지가 자동으로 뒤따랐고, 둘 다 시스템이 올바르게 동작한 결과입니다.

- `train_deepfake_detector.py`가 **`calibrated: true` 기록을 거부했습니다.** 홀드아웃
  AUC가 자신의 0.75 하한 아래였기 때문입니다. 이 가드는 결과를 알기 전에 작성되었습니다.
- 따라서 위험도 엔진은 **여전히 딥페이크 신호를 모든 점수에서 제외**하며, 모든 보고서의
  한계 항목에 그 사실을 명시합니다.

`blending` 백엔드는 그래도 함께 배포되지만 `usable: false`와 측정된 AUC가 모델 파일에
기록되어 있고, 자신이 산출하는 모든 점수에 붙는 비고에 그 AUC를 반복해서 적습니다. 우연
수준의 탐지기는 증거가 아니며, 코드는 독자가 반대로 넘겨짚게 두는 대신 그렇게 말합니다.

이것은 이 프로젝트의 전제를 가장 명확하게 확인해주는 사례입니다. 신호는 각각 독립적으로
실패하며, 이 신호를 위험 백분율에 접어 넣은 시스템이었다면 잡음을 포렌식이라고 보고하고
있었을 것입니다.

### 공개된 탐지기도 전이되지 않습니다

직접 만드는 데 실패했으니, 다음 단계는 만들기를 멈추고 사러 가는 것이었습니다. 공개된
체크포인트 세 개를 내려받아 각자의 전처리를 그래프에 구워 넣은 채 ONNX로 내보내고, 이
프로젝트의 기존 `onnx` 어댑터를 통해 파이프라인이 만들어내는 것과 동일한 얼굴 크롭에
돌렸습니다.

```bash
python scripts/fetch_deepfake_detector.py --model dima806
python scripts/evaluate_deepfake_detectors.py --write
```

| 탐지기 | HF 다운로드 수 | ROC-AUC | 자체 0.5 지점 재현율 | **실제 사진 오탐** | 판정 |
|---|---|---|---|---|---|
| `Wvolf/ViT_Deepfake_Detection` | 4,109 | 0.594 | 0.864 | **76.3%** | 사용 불가 |

AUC 열은 이 결과를 점잖게 읽는 방법입니다. 진짜 중요한 것은 오른쪽 열입니다. 가장 잘
분리하는 두 모델이 **진짜 사진 열 장 중 일곱 장을 합성이라고 부릅니다**. 누군가를 잘못
지목하지 않는 것이 존재 이유의 전부인 시스템에서 그런 탐지기는 탐지기가 없는 것보다
나쁩니다 — 게다가 가짜는 대부분 잡아내므로 잘 동작하는 것처럼 보이기까지 합니다.

세 번째 모델은 **우연 수준 이하**로, 이 자료에서 진실과 음의 상관을 갖는다는 뜻입니다.
이 모델은 라벨도 다른 둘과 반대(`Fake`이 클래스 0)인데, 이것이야말로 잘 동작하는 탐지기를
자신 있게 뒤집힌 탐지기로 바꿔놓는 배선 실수입니다. 내보내기 스크립트는 체크포인트 자신의
라벨 맵에서 합성 클래스를 해석하고 어느 인덱스를 골랐는지 기록하므로, 그런 실패는 나중에
발견되는 대신 그 자리에서 잡힙니다.

`--write`는 기준을 통과한 최고의 탐지기를 자동으로 채택합니다. 아무것도 채택하지
않았습니다. 오탐률 10% 미만에서 AUC 0.75라는 기준을 넘은 모델이 없었기 때문입니다.

**네 번의 독립적인 시도, 하나의 결론.** 손으로 만든 블렌딩 특징(0.58), 그리고 공개된
탐지기 셋(0.59, 0.59, 0.39). 딥페이크 신호는 위험 점수 밖에 남으며, 정직한 해석은 기성
합성 미디어 탐지가 학습 분포 바깥의 자료와 접촉하면 살아남지 못한다는 것입니다. 이는 이
프로젝트의 엔지니어링에 난 구멍이 아니라 하나의 발견이며, 다중 신호 설계를 지지하는 가장
강력한 논거입니다 — *실제로* 동작하는 신원 신호와 귀속 신호가 이 신호 없이도 시스템을
지탱합니다.

## 캘리브레이션

임계값은 논문에서 베껴온 것이 아니라 실제 데이터로 적합시켰습니다.

```bash
python scripts/fetch_sample_faces.py        # 퍼블릭 도메인 샘플
python scripts/calibrate_thresholds.py --write
```

YuNet + 랜드마크 정렬 + ArcFace + flip-TTA로, 다섯 가지 프로브 조건에 걸쳐 통합 측정:

```text
pooled: 850 genuine, 24650 impostor
ROC-AUC 1.0000   EER 0.0000
genuine  min=0.4397 p1=0.4899 median=0.7482
impostor max=0.3323 p99=0.1833
placement: gap [0.3323, 0.4397] width 0.1074; midpoint -/+ 25% of the gap
candidate threshold       0.3591  (recall 1.0000, 0 false positives)
high-confidence threshold 0.4128  (precision 1.0000, recall 1.0000, 0 false positives)
```

조건별로도 모두 깨끗하게 분리됩니다.

| 조건 | AUC | EER | 진짜 최솟값 | 사칭 최댓값 |
|---|---|---|---|---|
| 원본 | 1.0000 | 0.0000 | 0.566 | 0.279 |
| JPEG q30 | 1.0000 | 0.0000 | 0.553 | 0.288 |
| 20% 크롭 | 1.0000 | 0.0000 | 0.544 | 0.287 |
| 블러 σ=3 | 1.0000 | 0.0000 | 0.440 | 0.332 |

**이 캘리브레이션은 여전히 잠정적이며 코드도 그렇게 말합니다.** 벤치마크 하나에서 뽑은
30개 신원은 배포 대상 집단이 아니고, 한 신원 내부의 비교는 독립적이지 않습니다. 보고서는
신원 수와 사진 수를 기록하며, `deepshield info`는 각 임계값이 어느 파일에서 왔는지
출력합니다. 딥페이크 임계값은 여전히 캘리브레이션되지 않은 상태입니다 — 여기에는 라벨링된
딥페이크 데이터가 없습니다 — 따라서 그 신호는 모든 위험 점수에서 제외됩니다.

SFace를 대상으로 한 SPSA 클로킹을, 변환만 적용한 기준선과 비교해 측정:

|---|---|---|---|---|
| *기준선: 클로크 없이 JPEG-70만* | *0.022* | — | — | — |
| *기준선: 클로크 없이 resize-50만* | *0.046* | — | — | — |

보존하고, 기본 비활성화하며, 보호 수단으로 제시하지 않습니다.

### 결합 보호 (RQ4)

`./bin/deepshield robustness-test data/test/faces --experiment combined`:

| 조건 | PSNR | SSIM | 얼굴 유사도 | 워터마크 복원 |
|---|---|---|---|---|
| 원본 | — | 1.000 | 1.000 | 0/5 |
| 워터마크만 | 38.7 | 0.927 | 0.986 | 5/5 |

유지합니다. 지각적 비용은 누적되고(SSIM 0.927 → 0.850), 둘 중 어느 것도 얼굴 유사도를
의미 있게 낮추지 못합니다.

### 평가 정책

정확도만 단독으로 보고하는 일은 결코 없습니다. 얼굴 매칭은 TPR, FPR, ROC-AUC, EER,
정밀도, 재현율로 판단합니다. 워터마킹은 탐지율, 비트 정확도, 오귀속률로 판단합니다.
적대적 보호는 화이트박스, 모델 간, 변환 후 변위를 각각 따로 보고합니다. 이미지 품질은
PSNR과 SSIM입니다.

### 연구 질문

- **RQ1** 워터마크가 수용 가능한 품질에서 소셜 미디어 변환을 견디는가? 그리드
  재동기화 이후 **압축, 리스케일, 크롭에 대해서는 그렇다**(15/17). 회전과 강한 축소는
  여전히 이를 무력화한다.
- **RQ2** 클로킹이 JPEG, 리사이즈, 크롭, 스크린샷을 견디는가? **아니다 — 변환 자체보다
  약하다.**
- **RQ3** 클로킹이 얼굴 모델 간에 전이되는가? **거의 안 된다** — 0.080 대비 0.027.
- **RQ4** 워터마킹과 클로킹이 서로 간섭하는가? **아니다.** 다만 품질 비용은 누적된다.
- **RQ5** 다중 신호 융합이 오탐을 줄이는가? 구현되어 위험도 출력에서 확인할 수 있다.
  RQ8이 부분적으로 답한다. 딥페이크 신호에만 의존한 시스템이었다면 우연 수준의 점수를
  포렌식이라고 보고하고 있었을 것이다.
- **RQ8** 로컬에서 생성한 얼굴 교체로 손수 만든 블렌딩 탐지기를 캘리브레이션할 수
  있는가? **아니다** — 홀드아웃 AUC 0.579, 표본 내 0.641.
- **RQ9** 공개된 딥페이크 탐지기가 이 자료로 전이되는가? **아니다** — 체크포인트 셋이
  AUC 0.59, 0.59, 0.39를 기록했고, 그중 가장 나은 둘은 진짜 사진의 70% 이상을 합성이라고
  판정한다. 이 신호는 위험 점수 밖에 남는다.
- **RQ6** 샘플링 빈도 대비 정확도와 비용은? **측정함.** 두 사람이 등장하는 클립에서
  0.5fps부터 10fps까지 모든 비율에서 신원이 복원되며, 비용은 프레임 수에 비례한다.
  1fps는 0.29초에 유사도 0.942로 복원하고, 10fps는 0.88초에 0.975에 도달한다. 추가
  프레임이 사는 것은 판정 임계값이 필요로 하지 않는 정확도이며, 그래서 1fps가 기본이다.
- **RQ7** 트래킹과 대표 프레임이 재현율을 해치지 않으면서 비용을 줄이는가? 구현했다.
  프레임마다가 아니라 트랙마다 임베딩 하나.

## 한계

1. **학습 데이터 귀속 없음.** 설계상 범위 밖입니다.
2. **캘리브레이션은 잠정적입니다.** 인구 통계와 포즈에서 편향된 벤치마크인 LFW의 30개
   신원이며, 동일 신원 내 비교는 독립적이지 않습니다. 실제 사용 전에 배포 대상 집단과
   닮은 데이터로 재적합하십시오.
3. **딥페이크 신호는 캘리브레이션되지 않았고 위험 점수에서 제외됩니다.** 네 번의 시도로도
   이를 바꾸지 못했습니다. 손수 만든 블렌딩 탐지기(AUC 0.58)와 공개 체크포인트
   셋(0.59, 0.59, 0.39)이며, 그중 가장 나은 것도 진짜 사진의 70%를 합성으로 표시합니다.
   `onnx` 어댑터는 배선되고 테스트되어 준비되어 있습니다. 없는 것은 일반화되는
   모델이고, 그것은 데이터 사용 동의서 뒤에 있는 실제 라벨 코퍼스를 필요로 합니다.
4. **워터마크는 회전과 강한 축소에서 죽고**, 작은 이미지에서는 더 일찍 죽습니다. 30%
   크롭과 JPEG q50은 512픽셀 이미지에서는 살아남지만 250픽셀 이미지에서는 아닙니다.
   크롭 복원 비용은 미탐지 이미지당 약 0.3초입니다.
5. **클로킹은 동작하지 않습니다** — 수용 가능한 품질 예산에서는 그렇습니다. 위에서
   측정했습니다.
6. **검출이 실패하면 얼굴 인식도 실패합니다** — 강한 크롭과, 이미 작은 이미지의 4배
   축소는 아예 검출을 만들어내지 못합니다. 또한 학습 세트의 인구 통계 편향을 물려받으며,
   LFW는 그것을 측정하기에 잘못된 세트이고 이 프로젝트는 그 측정을 시도하지 않습니다.
7. **영상 트래킹은 휴리스틱입니다.** IoU와 색 히스토그램 외형 검사로 컷을 넘나드는
   인물을 분리하지만, 빠른 움직임과 교차하는 얼굴은 여전히 이를 무력화합니다. 과분할
   쪽으로 기울도록 튜닝되어 있는데, 트랙이 병합되면 보고서에서 한 사람이 조용히
   사라지기 때문입니다.
8. **C2PA는 선언된 스텁입니다.** `verify()`는 거짓 음성 대신 `supported: false`를
   반환하므로, 호출자가 "자격증명 없음"과 "확인 불가"를 구분할 수 있습니다.
9. **웹 모니터링 없음.** 입력은 사용자가 제출한 것뿐입니다.

## 프라이버시

얼굴 임베딩은 생체 식별자이며 민감 데이터로 취급됩니다.

- 신원 메타데이터와 임베딩 벡터는 **서로 다른 디렉터리**에 기록되므로, 생체 저장소만
  따로 권한을 걸거나 암호화하거나 삭제할 수 있습니다.
- 임베딩, 등록된 신원, 보호된 자산, 출처 원장은 git에서 제외됩니다. 파이프라인이
  기록하는 실행 상태이지 소스가 아니며, 저장소에 커밋되는 얼굴 이미지는 퍼블릭
  도메인 샘플(`data/test/faces/`) 뿐입니다. 평가 세트와 조작 세트도 제외되며,
  실명이 붙은 실존 인물의 크롭과 얼굴 교체 결과물이기 때문입니다. 둘 다
  `build_evaluation_set.py`와 `build_manipulation_set.py`로 재생성하십시오.
- 로그에는 전체 임베딩이 담기지 않습니다. `safe_embedding_repr`이 미리보기와 되돌릴 수
  없는 다이제스트로 잘라내고, `EmbeddingRedactionFilter`가 원시 벡터를 담고 있다고
  표시된 레코드를 버립니다.
- 워터마크 페이로드에는 불투명한 식별자만 담기며, 이름·이메일·핸들은 결코 담기지
  않습니다. 코드와 메타데이터의 연결은 데이터베이스가 맡습니다.
- 모든 생체 타입의 `to_dict()`는 구조적으로 원시 벡터를 생략합니다.
- 사용자 id는 파일명으로 쓰이기 전에 정제되므로, 어떤 식별자도 자신의 디렉터리를
  벗어날 수 없습니다.

## 개발

```bash
make test    # pytest
make lint    # ruff, mypy
make info    # 설정과 백엔드
make clean
```

현재 상태: **테스트 479개 통과 · 3개 건너뜀, ruff 클린, 소스 51개 파일에 대해 mypy
클린.** 건너뛴 3개는 `torch` 미설치 때문이며, `torch` extra를 넣으면 실행됩니다.
위 설치 명령과 깨끗한 클론에서 측정한 값입니다.

**테스트는 모델을 내려받지 않습니다.** `enroll`과 `analyze-image`가 파이프라인을
만들기 전에 입력 경로를 먼저 검사하므로, 오타 난 경로는 다운로드 실패가 아니라
"not found"로 보고되고 스위트는 `models/`가 비어 있어도 망 없이 통과합니다. 검사보다
먼저 백엔드가 만들어지면 실패하는 회귀 테스트가 이를 지킵니다(PR #1).

코드는 프로덕션 스타일입니다. 타입 힌트, 독스트링, 명시적 예외 타입, 설정 분리, 로깅,
그리고 인라인 주석 없음. 모든 단계가 동일한 루프를 따랐습니다 — 구현, 단위 테스트, 샘플
테스트, 지표 계산, 실패 기록, 이 README 갱신.

가치 순으로 본 다음 단계입니다.

1. **일반화되는 딥페이크 탐지기.** 지금까지 네 번 측정했고 — 직접 만든 것 하나, 공개된
   것 셋 — 전부 이 자료에서 우연 수준이거나 그 이하입니다. 어댑터, 내보내기 경로, 조사
   하네스, 채택 가드는 모두 만들어져 테스트되어 있습니다.
   `evaluate_deepfake_detectors.py --write`가 오탐 10% 미만에서 AUC 0.75를 넘는 첫
   모델을 연결할 것입니다. 없는 것은 그 모델이고, 그것은 FaceForensics++나 Celeb-DF
   같은 실제 라벨 코퍼스 위에서의 학습을 필요로 합니다. 둘 다 서명된 데이터 사용
   동의서를 요구하며, 이는 이 저장소가 스스로 밟을 수 없는 유일한 단계입니다.
2. **회전 불변 워터마크 동기화.** 그리드 탐색이 다루지 못하는 유일한 기하학적
   공격입니다.
3. **보도 사진 벤치마크가 아니라 실제 배포 집단과 닮은 캘리브레이션 세트.**

MVP에서 의도적으로 제외한 것: 인터넷 전역 크롤링, 완전한 C2PA 인프라, 학습 데이터 귀속,
제품 판정으로서의 멤버십 추론, 데이터셋 추론, 머신 언러닝, 학습 세트 오염, 그리고 모든
생성기나 워터마크 공격에 대한 보편적 커버리지.
